# LinkUp v0.7.0-beta.6

## Event visibility controls

- Adds a host-facing visibility control when creating and editing events.
- Keeps **Verified students at my school** as the safe default.
- Adds **Verified students in my district** for events intended to reach students across verified schools in the same district.
- Persists the selected scope through event creation and editing while preserving the existing district feed behavior.
- Does not expose public, cross-district, or custom visibility in this release.

## Security

- Firestore accepts only `school` or `district` visibility for user-created events.
- New events remain bound to the verified host's server-controlled school and district.
- Existing events may switch between school and district visibility, but `createdBy`, `school`, and `district` remain immutable from the client.
- Unsupported `public` visibility and forged cross-school or cross-district writes are rejected.
- Host-created events must begin with server-compatible moderation defaults; clients cannot self-approve an event, forge reviewer metadata, alter the initial attendee count, or inject undeclared fields.
- Event categories and optional RSVP/end timestamps are validated again at the Firestore boundary so a modified client cannot bypass form validation.
- Creation, update, and first-publication timestamps must be server timestamps so clients cannot forge ordering or audit history.

## Maintenance

- Replaces the release-specific beta.6 validation workflow with permanent, version-neutral LinkUp pull-request validation.
- Updates Next.js and its lint configuration to 16.3, refreshes the Firebase 12.x client, and pins the patched WebSocket driver to remove known high/critical production dependency findings without downgrading Firebase Admin.
- Aligns the Firestore category allowlist with the application's canonical event categories and adds a regression test to prevent drift.
- Moves CI to supported Node 22, Node 24-based GitHub actions, and Java 21 for the Firebase emulator instead of deprecated runtimes.
- Cancels superseded validation runs and caps them at 15 minutes to avoid wasting Actions minutes on stale or hung builds.

## Testing

- Adds unit coverage for school and district visibility validation and unsupported visibility rejection.
- Adds Firestore Rules Emulator coverage for school/district event creation, visibility changes, and forged identity/scope writes.
- Full validation must pass on a GitHub-hosted runner: `npm ci`, `npm test`, `npm run test:rules`, `npm run lint`, `npm run typecheck`, `npm run build`, and `git diff --check`.

## Review checklist

- Create a school-only event and confirm it appears to verified students at the same school.
- Confirm the school-only event is not readable from a different school in the same district.
- Create a district-wide event and confirm it appears to verified students at another school in the same district.
- Confirm the district-wide event is not readable from a different district.
- Edit an event from school-only to district-wide and back again.
- Confirm drafts remain visible only to their host until published.
- Confirm event creation still derives school and district from the verified profile rather than client-entered identity fields.

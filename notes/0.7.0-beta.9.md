# LinkUp 0.7.0-beta.9

## Reliable event drafts

- Fixed event creation when the host leaves the category selector at its
  default value by using the supported `academic` category.
- Added a Firestore regression test covering every category exposed by the form.
- Added a private **Your drafts** workspace where hosts can continue editing or preview unpublished events.
- Changed **Save draft** to redirect to the draft workspace instead of briefly entering an inconsistent event-detail/feed state.
- Added draft entry points to the Events header and navigation menu.
- Made host access to a draft explicit in client-side event authorization, matching the existing Firestore owner rule.
- Added a realtime listener error state so event details cannot remain stuck after access changes.
- Kept the published feed isolated to `status == "published"` events and added a regression test proving a draft cannot displace published results.
- Removed the draft action when editing an already-published event so a host cannot accidentally unpublish a live event. Published edits remain live and retain their original publication timestamp.

## Security and query behavior

- Draft listing queries are constrained by `createdBy == currentUser.uid` and filtered to drafts in the client.
- No cross-student draft access was added: Firestore continues to allow only the host to read an unpublished event.
- The owner query deliberately avoids an additional composite index while the number of host-created events remains small.

## Validation

- Unit tests cover host draft access and peer denial.
- Firestore emulator tests cover the owner-only drafts query and published-feed isolation.
- Lint, TypeScript, production build, and the complete test suite must pass before merge.

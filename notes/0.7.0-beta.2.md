# LinkUp v0.7.0-beta.2

Phase 3 attendance and event-detail completion patch.

## Added

- Transaction-backed event RSVPs with atomic attendee counts.
- Capacity and RSVP-deadline enforcement for new attendees.
- Duplicate attendance prevention and count-safe leave handling.
- Live attendance totals on event details.
- Persistent saved events and native share/copy-link support.
- Attendee profile pages with public bio and interests.
- A clearly labeled host-only **Preview RSVP flow (beta)** control so the
  one-person test team can exercise the attendee experience.

## Security

- Client writes to attendee and event-preference records are denied. The
  verified server route now owns those writes and validates event visibility,
  profile completion, capacity, and deadlines in one transaction.
- RSVP preference discovery is limited to the viewer's school.
- Saved-event records can only be read or changed by their owning user.

## Testing

- Added attendance policy tests for duplicate joins, full events, expired
  deadlines, leaving, and the temporary host-preview exception.
- Added Firestore emulator coverage for server-only RSVP writes, school-scoped
  preference reads, and saved-event ownership.
- Unit tests, lint, TypeScript, and the Next.js production build pass locally.

## Deployment note

Deploy `firestore.rules` with the application. The host RSVP exception is
centralized as `ALLOW_HOST_RSVP_PREVIEW` in
`app/lib/events/attendance.ts` so it can be removed cleanly after beta testing.

Event-image uploads remain deferred until the shared Firebase Storage and image
moderation pipeline is implemented. “Friends attending” remains tied to the
Phase 5 friend graph rather than shipping a fake approximation in Phase 3.

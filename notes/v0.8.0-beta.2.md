# LinkUp v0.8.0-beta.2

## Draft editing permission fix

This patch repairs the **Continue editing** action for private event drafts.

## Changes

- Added an authenticated host-only event endpoint for loading editable event
  data.
- Updated the edit page to use the same server-verified ownership path as the
  working drafts list instead of making a separate browser Firestore read.
- Kept draft contents private: the endpoint returns an event only when the
  verified token belongs to its creator.
- Added regression tests for host access and cross-account draft isolation.

## Why this is needed

The drafts page already loaded through a verified server endpoint, while the
edit page fetched the selected draft directly from Firestore in the browser.
That inconsistent access path could list a draft successfully and then reject
the same host when they clicked **Continue editing**. Both flows now use the
same authentication and ownership boundary.

## Validation

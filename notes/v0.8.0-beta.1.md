# LinkUp v0.8.0-beta.1

## Pilot interface release

This release gives LinkUp's authenticated experience a consistent, pilot-ready
desktop shell while preserving the mobile-first navigation and the tested event,
draft, RSVP, profile, and recommendation behavior from v0.7.0-beta.11.

## Changes

- Added a persistent desktop navigation rail for Events, Create, Drafts, and
  Profile, with a separate admin entry that only appears when the server reports
  administrative access.
- Kept the compact bottom navigation on mobile and removed duplicate desktop
  navigation controls.
- Added a centered feed with an optional desktop context rail, clearer school
  visibility language, and a direct event-creation action.
- Applied the LinkUp blue, lavender, and coral visual language to authenticated
  event, RSVP, draft, profile, and attendee surfaces.
- Improved card hierarchy, responsive spacing, active navigation states, focus
  visibility, reduced-motion support, and pressed feedback for interactive
  controls.
- Preserved the existing public login and signup presentation, authentication
  guards, school/district visibility rules, recommendation ordering, draft
  privacy, and server-enforced RSVP policy.

## Why this is needed

The pilot must feel like one product rather than a collection of independently
styled pages. A shared shell reduces navigation dead ends, exposes host drafts,
keeps admin tools visually distinct, and makes the primary student journey easier
to understand without changing the security-sensitive data layer immediately
before launch.

## Validation

- `npm test` — 99 tests passed.
- `npm run lint` — passed with zero warnings.
- `npm run typecheck` — passed.
- `npm run build` — passed on Next.js 16.3.0.
- `npm run test:rules` — deferred to GitHub Actions because the isolated local
  runner could not start the Firestore emulator network dependency. No Firestore
  rules or query shapes changed in this release.

## Pilot review checklist

- Verify login and signup at desktop and phone widths.
- Confirm the desktop rail highlights Events, Create, Drafts, and Profile.
- Confirm admin tools appear only for an authorized admin account.
- Create and publish an event, save a separate draft, and return to both.
- Join an event, open its attendee list, and view an attendee profile.
- Confirm a non-admin, same-school student cannot see drafts or admin tools.
- Confirm school-only events do not appear to a different school account.
